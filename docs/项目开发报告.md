# 云师大校园导览系统 — 项目开发报告

> 课程：地理信息服务平台 | 2026 年 6 月

---

## 一、项目概述

### 1.1 项目背景

云南师范大学呈贡校区占地广阔，拥有 60 余栋建筑，新生和访客经常面临"找路难"的问题——不知道某栋楼在哪、食堂有什么吃的、校园里有什么活动可以参加。现有的校园地图多为静态图片，缺乏交互性和实时信息。

### 1.2 项目目标

开发一个基于 Web 的智慧校园 GIS 导览平台，集成地图浏览、建筑搜索、路径导航、活动日历等功能，支持桌面和手机双端使用，并通过 GitHub Pages 实现零成本部署。

### 1.3 开发环境

| 项目 | 技术 |
|------|------|
| 地图引擎 | 高德地图 JS API 2.0 |
| 前端 | 原生 HTML + CSS + JavaScript（无框架）|
| 后端 | Node.js + Express |
| 数据存储 | JSON 文件 |
| 版本管理 | Git + GitHub |
| 部署 | GitHub Pages |

## 二、开发过程

### 2.1 第一阶段：基础搭建（6 月 6 日）

**目标**：搭建项目骨架，实现最基本的地图展示和建筑标注。

**完成内容**：
- 初始化 Node.js 项目，安装 Express 依赖
- 搭建 RESTful API（buildings、canteens）
- 创建地图主页，加载高德地图
- 实现建筑标注（Marker）渲染和点击弹窗
- 实现搜索功能、后台管理页面、坐标校准器

**技术决策**：
- 选择高德地图而非百度/Google：高德在国内精度最高，API 文档完善，免费额度充足
- 选择 JSON 文件存储而非数据库：数据量小（<100 条），JSON 简单可靠，方便 Git 版本管理
- 不用前端框架：项目是单页面应用，原生 JS 足够，避免引入框架的学习成本和打包步骤

### 2.2 第二阶段：静态化改造（6 月 9 日）

**目标**：让项目能在 GitHub Pages 上运行，实现零成本部署。

**完成内容**：
- 设计双模式架构：服务器 API + 内嵌静态数据自动切换
- 将建筑数据内嵌到 `js/data.js`，无需后端也能加载
- 新增侧边栏 UI：学校介绍、天气、搜索、分类标签、建筑卡片
- 批量坐标校准（高德 POI 搜索修正 38 栋建筑坐标）
- 新增校园活动/公告功能
- 新增 AI 代码快照工具（一键生成单文件给 AI 分析）

**关键问题与解决**：
- **问题**：GitHub Pages 无法运行 Node.js
- **解决**：设计 API 代理层（`api.js`），启动时检测服务器可用性，不可用时自动使用内嵌的 `EMBEDDED_BUILDINGS` 数据，一套代码无需修改

### 2.3 第三阶段：数据建设（6 月 10 日 - 6 月 16 日）

**目标**：扩充建筑数据，让平台有真实可用的信息。

**完成内容**：
- 将建筑数据从 38 栋扩充到 63 栋，覆盖学校主要建筑
- 每栋建筑补充详细简介、开放时间、联系电话
- 3 个食堂录入完整菜单（楼层、窗口、菜品、价格）
- 42 栋建筑实地拍摄照片
- 搜索升级：支持拼音搜索（如 "jxl" → "教学楼"）、自然排序、键盘导航

**数据来源**：
| 类型 | 来源 |
|------|------|
| 建筑名称/分类 | 学校官网 + 实地走访 |
| 经纬度坐标 | 高德地图坐标拾取器 |
| 建筑简介 | 学校官网院系介绍 + 公开资料 |
| 食堂菜单 | 实地调研 |
| 建筑照片 | 团队实地拍摄 |

### 2.4 第四阶段：导航功能（6 月 16 日）

**目标**：实现完整的校园路径规划功能。

**完成内容**：
- 步行导航（AMap.Walking）
- 驾车导航（AMap.Driving）
- 骑行导航（AMap.Riding）
- 多路线方案展示与切换（驾车 3 种策略：最快/最短/省钱）
- ETA 预计到达时间
- 导航信息卡（桌面端常显，手机端可折叠）
- 导航时自动关闭详情面板和建筑面板，避免遮挡路线

**技术难点**：
- **骑行导航**：高德 Riding 插件文档较少，经过多次调试才正确集成
- **路线方案切换**：驾车使用不同 policy 参数实现真实的变化，步行和骑行需要重新调用 API 获取不同路线

### 2.5 第五阶段：手机端适配（6 月 16 日）

**目标**：手机端全面优化，桌面端保持不变。

**第一版（抽屉方案）**：
- 侧边栏在手机端变为底部抽屉，触摸拖拽展开/收起
- 新增帮助按钮
- 搜索栏在导航时自动隐藏

**问题**：
- 抽屉遮挡地图核心区域
- 手势拖拽与地图操作冲突
- 浏览器兼容性问题（DOMMatrixReadOnly 旧浏览器不支持）

**第二版（浮层方案，最终版）**：
- 完全重写手机端布局：地图全屏，功能以浮层覆盖
- 顶部：搜索栏 + 分类横滑标签
- 左下：🏠 建筑列表浮动按钮 → 半屏面板
- 右下：⋮ 功能菜单（矢量/卫星/3D/帮助/图例）
- 底部：活动横条
- 毛玻璃效果 + 手势拖拽关闭
- 桌面端代码完全不动，仅通过 `@media (max-width: 768px)` 隔离样式

**技术亮点**：
- `backdrop-filter: blur(10px)` 实现毛玻璃效果
- `transform: translateY(100%)` 实现面板滑入滑出动画
- `touchstart/touchmove` 实现下拖关闭手势

### 2.6 第六阶段：修复与完善（6 月 16 日）

**Bug 修复**：
- 照片路径适配 GitHub Pages 子目录（绝对路径 → 相对路径）
- `buildings.json` 与 `data.js` 数据同步（38 栋 → 63 栋）
- 照片重复路径清理
- 桌面端图片显示恢复（CSS 冲突）
- 步行/骑行路线方案切换修复
- 搜索 `_id` 兼容修复

**文档完善**：
- README 全面更新
- 期末汇报 PPT 大纲 + 演讲逐字稿 + 答辩问答准备

### 3.2 双模式自动切换

```javascript
// api.js 核心逻辑
async function checkServer() {
  try {
    const res = await fetch('/api/buildings');
    if (res.ok) {
      useServer = true; // 服务器模式
      return true;
    }
  } catch (e) { }
  useServer = false;    // 静态模式
  return false;
}
```

## 五、问题与解决方案

| # | 问题 | 解决方案 |
|---|------|---------|
| 1 | GitHub Pages 无法运行 Node.js | 设计双模式架构，静态模式下自动使用内嵌数据 |
| 2 | 手机端抽屉遮挡地图 | 重写为浮层化 UI，信息覆盖在地图上 |
| 3 | 绝对路径在 GitHub Pages 子目录下 404 | 改为相对路径 `public/images/...` |
| 4 | buildings.json 与 data.js 不同步 | 统一以 data.js 为准，脚本同步到 JSON |
| 5 | 旧浏览器不支持 DOMMatrixReadOnly | try-catch + 正则 fallback 解析 matrix 字符串 |
| 6 | 手机端两个 @media 块冲突 | 删除旧块，合并必需样式到新块 |
| 7 | 导航双击调用 planRoute() | 移除 updateRouteBar()，统一由 planRoute() 处理 |
| 8 | 驾车路线方案切换无效 | 使用不同 policy 参数（0=最快, 1=省钱, 2=最短）|

## 十、总结

本项目从零开始，在 10 天内完成了一个功能完善的校园 GIS 导览平台。核心 GIS 能力覆盖地图可视化、空间查询、路径规划和 POI 信息服务，地图、搜索、导航三大功能实现完备。技术架构上，双模式自动切换保证了本地开发和线上部署的一致性，CSS 媒体查询实现了桌面端和手机端的独立适配，手机端的浮层化 UI 设计在有限屏幕空间内完整保留了所有功能。项目通过 GitHub Pages 实现了零成本的持续部署，可直接通过线上地址访问体验。
