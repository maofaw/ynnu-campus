**痛点**
- 新生和访客进校园经常迷路，不知道教学楼、食堂、宿舍在哪
- 学校没有统一的校园导览平台，信息分散

**我们的目标**
- 打造一个好看、好用、信息完整的校园 GIS 导览平台

**技术路线**
- 高德地图 JS API 2.0 + Node.js Express + GitHub Pages 部署

## 二、5 分钟演讲逐字稿

---

**【第 1 页 · 封面】（10 秒）**

> 大家好，我们小组做的是云师大校园导览系统，一个基于高德地图的智慧校园 GIS 平台。

**【第 2 页 · 选题背景】（30 秒）**

> 选这个题目的原因很简单——我们自己就是云师大的学生，刚入学的时候经常找不到路，不知道哪栋楼在哪，也不了解学校有什么活动可以参加。我们就想，能不能做一个校园导览平台，把地图、建筑信息、导航、活动都整合到一起，让所有师生和访客都能快速了解校园。
>
> 技术上我们选择了高德地图 JS API 2.0，配合 Node.js 做后端，最终部署在 GitHub Pages 上，完全免费。

**【第 3 页 · 功能总览】（40 秒）**

> 平台功能覆盖了校园导览的方方面面：地图支持矢量、卫星、3D 三种图层；搜索支持汉字和拼音；导航覆盖步行、驾车和骑行三种出行方式；每栋建筑都有独立的详情页，包含实拍照片、电话、开放时间，还能看到该建筑上举办的校园活动。另外我们还做了食堂菜单浏览和活动日历。所有这些功能在桌面端和手机端都能正常使用。

**【第 4 页 · GIS 核心能力】（40 秒）**

> 作为地理信息服务平台，我们的 GIS 核心能力体现在四个方面。第一是地图可视化，63 栋建筑全部精准标注，8 种分类用不同颜色区分。第二是空间查询，支持模糊搜索和拼音搜索，配合分类筛选，能快速定位目标建筑。第三是路径规划，我们调用了高德地图的步行、驾车和骑行 API，支持多路线方案切换，还能显示预计到达时间。第四是 POI 信息展示，每栋建筑都关联了详细属性数据和校园活动，形成了一个完整的校园 POI 数据库。

**【第 5 页 · 技术架构】（40 秒）**

> 技术架构上，前端用原生 HTML、CSS 和 JavaScript 开发，没有使用任何框架，保证了加载速度和兼容性。后端是 Node.js Express 框架，提供 RESTful API，数据存储在 JSON 文件中。特别要提的是我们设计了一个双模式自动切换机制：平台启动时会自动检测服务器是否可用，可用就用 API 动态加载数据，不可用时——比如部署在 GitHub Pages 上——会自动切换到内嵌的静态数据，保证平台始终正常运行。部署方面我们用 GitHub Pages，完全免费，推送代码就能自动上线。

**【第 6 页 · 多端适配】（30 秒）**

> 多端适配方面，桌面端采用经典的侧边栏加地图布局，信息一目了然。手机端我们做了比较大的改动——地图全屏显示，搜索、分类、功能菜单全部以浮层的形式覆盖在地图上，用了毛玻璃效果和手势交互，既不遮挡地图又保证了功能完整性。两端的样式通过 CSS @media 查询完全隔离，同一套代码互不影响。

**【第 7 页 · 数据建设】（30 秒）**

> 数据方面我们花了大量精力。63 栋建筑每一栋都有完整的名称、经纬度、分类和简介，部分建筑还加了开放时间、电话等信息。42 栋建筑有团队实地拍摄的照片。3 个食堂的完整菜单，包含具体楼层、窗口、菜品和价格，都是实际调研得来的。还有 5 条真实的校园活动数据。

**【第 8 页 · 创新亮点】（30 秒）**

> 创新方面，我们做了几个比较有意思的功能：骑行导航在校园场景里特别实用，比步行快比驾车灵活。路线方案切换让用户可以选择最快、最短或者最省钱的路线。手机端的浮层化 UI 是我们自己设计的，交互体验比较现代。最后就是完全零成本的部署方案，服务永远在线。

## 三、答辩常见问题准备

---

### Q1：数据怎么来的？

**答**：建筑基础数据来自学校官网和公开资料，坐标通过高德地图坐标拾取器获取。42 栋建筑的照片是团队成员实地拍摄的。食堂菜单和菜品价格是实际走访调研记录的结果。

### Q2：为什么选高德地图？和百度、Google 地图比有什么优势？

**答**：高德地图在国内的覆盖最全、API 文档最完善，而且对学校和科研用途有免费额度。百度地图的 API 设计类似但生态略差，Google 地图在国内加载不稳定。另外高德的路径规划引擎在国内精度更高，步行和骑行数据也更准确，非常适合校园场景。

### Q3：路线规划的算法是你们自己写的吗？

**答**：路线规划调用了高德地图的官方 API——AMap.Walking、AMap.Driving 和 AMap.Riding。我们的工作是把这三个 API 集成到统一的导航流程里，并实现了路线方案的展示和切换。路径计算本身由高德后端引擎完成，它们有实时路况和道路网络数据，比自己写算法更可靠。

### Q4：手机端为什么不用小程序或 App？

**答**：Web 方案有几个优势：第一，不需要用户安装任何东西，打开浏览器就能用；第二，一套代码同时适配桌面和手机，开发和维护成本低；第三，部署简单，GitHub Pages 就能托管。小程序和 App 虽然体验可能更好，但开发成本高、审核流程长，对于课程项目来说 Web 是性价比最高的选择。

### Q5：怎么保证数据实时更新？

**答**：目前活动数据通过定时轮询机制更新，每 5 分钟检查一次服务器数据。建筑基础数据变化频率低，手动维护即可。如果未来接入学校官方数据接口，可以实现自动同步。平台的双模式架构也支持随时切换到服务器模式获取最新数据。

### Q6：地图加载速度怎么优化？

**答**：高德 JS API 采用按需加载，只加载用到的模块（Walking、Driving、Riding）。数据层面，静态部署时数据内嵌在 JS 文件中，不需要额外请求。图片用了懒加载策略。首次加载约 2-3 秒，后续有浏览器缓存会更快。

### Q7：你们团队怎么分工的？

**答**：（按实际填写）一人负责前端开发和 UI 设计，一人负责后端 API 和数据库，一人负责数据采集和照片拍摄，一人负责测试和文档。整个开发过程中通过 Git 管理代码，每个功能在独立分支上开发，完成后再合并。

### Q8：这个平台有哪些可以改进的地方？

**答**：第一，可以接入学校官方的建筑和活动数据接口，实现真正的实时更新。第二，室内导航是一个大方向，可以帮助用户在大型建筑（如图书馆）内部导航。第三，可以考虑增加用户反馈功能，让师生上报建筑信息变更或新增活动。第四，可以做成 PWA 渐进式 Web 应用，支持离线使用和添加到主屏幕。
